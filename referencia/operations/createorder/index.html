Crear pedido

POST
/orders

Crea un pedido con una o más cuentas (tabs), cada una con sus items. Es idempotente por external_id: si ya existe un pedido con ese mismo external_id para tu app, te devuelve 409 con el id del pedido existente en lugar de crear uno nuevo.

Requiere scope orders:write.

external_id
obligatorio

ID único del pedido dentro de tu sistema. Se usa para idempotencia — si reenvías el mismo pedido, te devolvemos 409 en vez de duplicarlo.

La unicidad la garantiza la base (UNIQUE (external_app, external_id)), y es por aplicación: dos integradores pueden usar order-123 sin pisarse.

string
<= 64 characters
Example
reference

Identificador del pedido para humanos o periféricos. No es un ID de sistema: el número de orden que ve el cliente en tu app de delivery, un código de seguimiento, algo que alguien lee en voz alta o que un lector escanea.

No confundir con external_id, que es el ID que tu sistema ya tiene para ese registro. reference describe, external_id identifica, id direcciona.

En el POS este mismo campo es el código manual o de NFC que el cajero escanea (identificador), no el número de pedido — ese es order_number.

Es único entre los pedidos ABIERTOS del mismo local: si reusás uno que sigue abierto, recibís 409 conflict con 'reference' is already used by another open order. Al cerrarse el pedido, el código se libera y se puede reusar.

Tu identificador de ESTA cuenta dentro de tu sistema. Se guarda y se devuelve tal cual, para que puedas correlacionar la cuenta de vuelta contra tu lado.

Es el ID de tu registro, no una etiqueta para leer en voz alta — para eso está reference.

No es una llave de idempotencia: la única que lo es está en OrderInput.external_id, a nivel de pedido. Reenviar dos cuentas con el mismo external_id no da 409.

reference

Identificador de la cuenta para humanos o periféricos. El número de cliente, el código RFID de una pulsera, el número de silla — algo que una persona dice o que un lector escanea para saber de quién es esta cuenta.

No es un ID de sistema. Si tu sistema ya tiene un id para esta cuenta, ese va en external_id.

Se guarda y se devuelve idéntica. RunFood no la interpreta ni la usa para buscar: no aparece en impresiones, webhooks, filtros ni reportes, y tab_ref no la acepta.

No es única — dos cuentas del mismo pedido pueden compartirla, porque dos personas pueden traer la misma pulsera reasignada. No direcciona: para apuntar a una cuenta se usa tab.id (ADR 0002).

discount

Monto descontado de esta línea. Absoluto, no por unidad: 2 unidades con 0.30 de descuento cada una se declaran como 0.60.

Nunca se declara un descuento como precio negativo: unit_price siempre es ≥ 0. El descuento baja la base imponible y el IVA, y viaja al comprobante electrónico por línea.

number
<= 1000000
Example
line_total

Neto que TÚ calculaste para esta línea: round(unit_price × quantity, 2) − discount, sin IVA.

Se verifica, no se usa para calcular. RunFood calcula el suyo y compara; si no coinciden responde 422 line_mismatch diciendo qué fila y cuánto esperaba.

La comparación es exacta (solo se absorbe ruido de punto flotante, 0.005). No hay banda de un centavo acá: el SRI valida totalSinImpuestos == Σ precioTotalSinImpuesto sin tolerancia, así que un centavo perdonado en la línea es un comprobante rechazado.

Es opcional, pero declararlo es la diferencia entre enterarte acá de que una fila no cuadra, o enterarte al facturar de que el total difiere en un monto que ninguna de las dos partes puede atribuir a una fila.
