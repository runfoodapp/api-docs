Conectar un cliente real

Ya probaste contra la demo. Ahora tienes un restaurante de verdad que quiere usar tu app.

Lo que cambia respecto a la demo

Sección titulada «Lo que cambia respecto a la demo»
Demo Cliente real
URL base Fija y pública Distinta para cada local
API key Compartida Una tuya, para ese local
Datos De juguete, compartidos Reales. Las facturas van al SRI.
Disponibilidad Casi siempre arriba Se cae. Es un servidor dentro de un restaurante.

Cada local tiene su propia URL base

RunFood es on-premise: cada restaurante corre su propio servidor, con su propia base de datos y su propio catálogo. No existe una URL central a la que apuntar con un client_id.

La URL base de cada local te la entregamos junto con la API key. Tiene esta forma:

Si integras 50 restaurantes, guardas 50 pares de (URL base, API key). Diséñalo así desde el primer día: meterle multi-tenancy después a un cliente HTTP con la URL escrita a mano es doloroso.

Cómo se pide el acceso

Sección titulada «Cómo se pide el acceso»

El dueño del local tiene que autorizarlo. El trámite —a quién escribir, qué datos mandar y qué cuesta— está en Pasar a producción.

Los primeros cuatro pasos, en orden

Sección titulada «Los primeros cuatro pasos, en orden»

Cuando ya tengas la URL base y la clave:

1. Comprueba que el local responde

Sección titulada «1. Comprueba que el local responde»

No necesita API key. Si falla, el local está caído — y eso no es una excepción, es parte del día a día (por qué).

2. Averigua con quién estás hablando

Sección titulada «2. Averigua con quién estás hablando»
  • Guarda el ruc: es cómo sabes de qué local es cada dato en tu sistema.
  • Guarda taxes.vat_rate: lo necesitas para calcular totales y es distinto en cada local (Totales e impuestos).

3. Sincroniza el catálogo

Sección titulada «3. Sincroniza el catálogo»

Los sku y los payment_method_id son de ese local. No los compartas entre clientes: el sku de la Coca Cola en un restaurante no es el mismo que en otro.

Vuelve a sincronizar cada cierto tiempo — el local cambia precios y da de alta productos.

4. Suscríbete a los eventos

Sección titulada «4. Suscríbete a los eventos»

Guarda el secret que te devuelve: solo se muestra una vez.

Si integras muchos locales

Sección titulada «Si integras muchos locales»

El webhook no te dice de qué local viene

Si apuntas todos tus clientes al mismo endpoint, no vas a poder distinguirlos por el cuerpo del mensaje.

Usa un endpoint distinto por local — https://tu-servidor.com/hooks/runfood/cliente-42. Es lo más simple y no depende de nada del payload.

Checklist

Sección titulada «Checklist»
  • Guardo una URL base y una API key por local
  • Guardo el ruc de cada local (GET /identity)
  • Guardo la tasa de IVA de cada local — no la escribo en el código
  • Sincronizo sku y payment_method_id por local, sin mezclarlos
  • Uso un endpoint de webhook por local
  • Asumo que el local se va a caer: tengo cola de reintentos y reconciliación
