Empieza en 5 minutos

Antes de pedir credenciales de producción, prueba todo contra nuestro ambiente público de demo. No hace falta pedir permiso ni pagar nada — toma la API key de abajo y empieza.

Ambiente de demo

Sección titulada «Ambiente de demo»

URL base:

API Key (compartida, solo para pruebas):

Cuando autentiques con esta key y llames a GET /apps/me, vas a ver esta identidad:

Campo Valor
id fantastic_app
name Fantastic App
icon_url https://runfoodapp.com/fantastic_app.png
scopes orders:write, products:read, payment-methods:read, apps:read

Qué NO puedes hacer en la demo

La clave de demo no tiene permiso de facturación (invoices:write). Puedes crear pedidos, leer el catálogo y consultar métodos de pago — pero no puedes emitir facturas. Si lo intentas, recibes 403 insufficient_scope.

Es a propósito: una factura de demo seguiría siendo un comprobante emitido ante la autoridad tributaria. Para probar facturación necesitas credenciales de un local real (Pasar a producción).

Es una cuenta compartida

La usan todos los que están probando a la vez. Cualquiera puede modificar los datos — no guardes nada que te importe y no te sorprendas si ves pedidos que tú no creaste.

Tu primer pedido

Sección titulada «Tu primer pedido»

Un pedido no se inventa: sus productos tienen que existir en el catálogo de ese restaurante. Así que el orden es siempre el mismo — primero mira el catálogo, después pide.

1. Mira qué vende el local

Sección titulada «1. Mira qué vende el local»

Fíjate en el sku: es el código de ese producto en ese local, y aquí es una cadena opaca. En otro local podrían ser códigos legibles. No asumas un formato y no te lo inventes — cópialo de aquí.

2. Crea el pedido

Sección titulada «2. Crea el pedido»

Tres cosas que no son obvias y te van a hacer falta:

  • external_id es tuyo. Es el identificador del pedido en tu sistema. Si repites el mismo, RunFood responde 409 en vez de duplicar el pedido — eso es lo que te protege de cobrar dos veces cuando un reintento de red se cuela.
  • unit_price es obligatorio. Tú declaras a qué precio vendes; RunFood no lo toma del catálogo.
  • Un pedido tiene tabs (cuentas). Una cuenta es lo que se paga junto. Una mesa que “paga por separado” son varias cuentas dentro del mismo pedido. Cada cuenta produce una factura.

3. Léelo

Sección titulada «3. Léelo»

Ya está: el pedido existe en el POS del restaurante y salió por la impresora de cocina.
